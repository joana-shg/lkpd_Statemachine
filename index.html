Ringkasan Materi

1. Finite State Machine (FSM)

FSM adalah sistem dengan jumlah state terbatas yang berpindah karena event sambil menjalankan action. Prinsipnya: satu state pada satu waktu, ada initial state, dan bebas deadlock.

KomponenPenjelasanContoh
StateKondisi sistem saat iniIDLE, WATERING
TransitionPerpindahan stateIDLE → READING
EventPemicu transisiTimer 5 detik
ActionAksi yang dilakukan di statePompa ON
GuardSyarat transisiJika data valid

2. ASM vs FSM

ASM adalah FSM dalam bentuk diagram alur berblok, mirip flowchart: persegi panjang = state box, belah ketupat = decision box, oval = conditional output (Mealy). FSM ringkas untuk dokumentasi desain; ASM lebih rinci pada keputusan dan output.

4. Studi Kasus: Penyiraman Otomatis ESP32

5 state (IDLE, READING, EVALUATING, WATERING, ERROR), 7 transisi, threshold 60%.

  • IDLE → READING: timer 5 detik
  • READING → EVALUATING: data valid
  • READING → ERROR: sensor error
  • EVALUATING → WATERING: soil < 60%
  • EVALUATING → IDLE: soil ≥ 60%
  • WATERING → IDLE: 10 detik, pompa OFF
  • ERROR → IDLE: reset manual

Action: IDLE tunggu 5 detik · READING baca soil_moisture · EVALUATING bandingkan dengan threshold · WATERING pompa ON, tunggu 10 detik, pompa OFF · ERROR pompa OFF, notifikasi Blynk, tunggu reset.

Aktivitas 1: Identifikasi Komponen FSM

Seret label kuning ke kotak definisi yang tepat. Di layar sentuh: ketuk label, lalu ketuk kotaknya.

Pertanyaan 1: Mengapa state ERROR perlu dipisahkan dari state lain? Pertanyaan 2: Apa fungsi guard pada transisi READING → EVALUATING?

Aktivitas 2: Tabel Komponen FSM

Lengkapi event, guard, action, dan transisi untuk setiap baris. Jika tidak ada guard, tulis "—".
